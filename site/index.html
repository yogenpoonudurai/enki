Exposed AI endpoints

Ollama, LM Studio, ComfyUI, A1111, vLLM, Jupyter — bound to the network without auth or with permissive CORS.

MCP supply chain

Unpinned npx/uvx packages, plaintext remote servers, inline credentials, broad filesystem grants.

Agent permissions

bypassPermissions, unrestricted shell, auto-run, and allow-lists that reach ~/.ssh, ~/.aws, or GPG keys.

Secrets

Provider keys in configs, dotfiles, shell history, and MCP env — redacted and fingerprinted, never logged raw.

Model artifacts

Pickle checkpoints, trust_remote_code, torch.load without weights_only, weights fetched over plain HTTP.

Dependency CVEs

npm, PyPI, Go, Cargo, NuGet, and Linux packages — CVSS-scored, KEV/EPSS prioritized, grouped per package.

What ENKI does not do

ENKI does not instrument runtime behavior, inspect model weights, prove exploitability, or replace a full SCA or container scanner. Coverage gaps are reported explicitly, so “clean” never means “everything was visible”.

Open source, local-first.

The CLI, TUI, skills, local MCP server, SBOM export, SARIF/OCSF output, and fix/undo are open source and fully functional offline. AI triage with your own key (BYOK) is optional and free. No account or hosted service is required for any local feature.

Teams that want managed inference can use the optional paid hosted service: hosted AI triage, hosted MCP, history, policy, and SSO. Hosted service. Local detection is never gated.
